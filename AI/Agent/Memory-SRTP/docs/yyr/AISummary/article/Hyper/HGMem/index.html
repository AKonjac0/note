HGMem

论文概述
论文标题：Improving Multi-Step RAG with Hypergraph-Based Memory for Long-Context Complex Relational Modeling（arXiv:2512.23959v2 [cs.CL]，2026年1月2日）。
作者：Chulun Zhou¹∗、Chunkang Zhang∗、Guoxin Yu、Fandong Meng²、Jie Zhou²、Wai Lam¹†、Mo Yu²†（¹香港中文大学，²微信AI；∗并列一作，†共同通讯作者）。
代码仓库：https://github.com/Encyclomen/HGMem。

论文针对多步RAG（Multi-Step Retrieval-Augmented Generation）在长上下文、复杂关系建模任务中的痛点（现有记忆模块仅被动存储孤立事实，无法捕捉高阶关联），提出HGMEM：一种基于超图的动态记忆机制，将记忆从“静态存储”升级为“动态、高阶关系建模结构”。记忆以超图形式表示，超边（hyperedge）作为记忆单元，逐步形成更高阶的关联，从而为后续推理提供更强的全局洞察力。

核心方法论严格按照原文第3节（METHODOLOGY）的结构讲解，共6个小节。以下逐节展开（所有公式、定义、操作均忠实于原文，保留LaTeX表示）。

3.1 Problem Formulation（问题形式化）

任务输入：一个查询 \(\hat{q}\)，文档 \(\mathcal{D}\)（被分割成文本块 \(\{d_1, d_2, \dots, d_{|\mathcal{D}|}\}\)），以及一个离线构建的结构化知识图 \(\mathcal{G} = (\mathcal{V}_{\mathcal{G}}, \mathcal{E}_{\mathcal{G}})\)（节点 \(\mathcal{V}_{\mathcal{G}}\) 为实体，边 \(\mathcal{E}_{\mathcal{G}}\) 为关系）。
所有节点、边和文本块均被嵌入为向量，便于检索。LLM 可同时访问 \(\mathcal{D}\) 和 \(\mathcal{G}\)。记忆模块 \(\mathcal{M}\) 用于在多步迭代中管理已获取的信息。

3.2 Multi-Step RAG System with Memory（带记忆的多步RAG系统）

系统整体流程（对应论文Figure 1 (i)）：
给定查询 \(\hat{q}\)，LLM 在第 \(t\) 步判断当前记忆 \(\mathcal{M}^{(t)}\) 是否足够。若不足，则生成子查询集合 \(\mathcal{Q}^{(t)}\)，从 \(\mathcal{D}\) 和 \(\mathcal{G}\) 中检索新信息，并更新记忆。
- 实体检索（Entity Retrieval）：
$$ \mathcal{R}{\mathcal{V}}(\mathcal{Q}) = \bigcup}} \arg\max_{v \in \mathcal{V}}^{n_v} \operatorname{sim}(\mathbf{hq, \mathbf{h}_v) $$
其中 \(\operatorname{sim}\) 为余弦相似度，\(n_v\) 为每个子查询检索的实体数量上限。
- 第 \(t\) 步具体检索：从 \(\mathcal{M}^{(t)}\) 生成 \(\mathcal{Q}^{(t)}\) → 检索 \(\mathcal{V}_{\mathcal{Q}^{(t)}} = \mathcal{R}_{\mathcal{V}_{\mathcal{G}}}(\mathcal{Q}^{(t)})\) → 通过图索引获取关联边 \(\mathcal{E}(\mathcal{V}_{\mathcal{Q}^{(t)}})\) 和文本块 \(\mathcal{D}(\mathcal{V}_{\mathcal{Q}^{(t)}})\)（数量分别限制为 \(n_e\) 和 \(n_d\)）。
- 记忆演化：
$$ \mathcal{M}^{(t+1)} \leftarrow \mathrm{LLM}(\mathcal{M}^{(t)}, \mathcal{V}}^{(t)}}, \mathcal{E}(\mathcal{V{\mathcal{Q}^{(t)}}), \mathcal{D}(\mathcal{V})) $$}^{(t)}
初始时 \(t=0\)，\(\mathcal{Q}^{(0)} = \{\hat{q}\}\)。

3.3 Hypergraph-Based Memory Storage（基于超图的记忆存储）

这是HGMEM的核心创新。记忆表示为超图 \(\mathcal{M} = (\mathcal{V}_{\mathcal{M}}, \tilde{\mathcal{E}}_{\mathcal{M}})\)，其中：
- \(\mathcal{V}_{\mathcal{M}}\) 是实体节点集合（\(\mathcal{V}_{\mathcal{G}}\) 的子集）。
- \(\tilde{\mathcal{E}}_{\mathcal{M}}\) 是超边集合（每个超边即一个“记忆点”）。

每个节点（vertex）：
$$ v_i = (\Omega^{\text{ent}}{v_i}, \mathcal{D}) $$
（\(\Omega^{\text{ent}}_{v_i}\) 为实体名称+描述，\(\mathcal{D}_{v_i}\) 为关联文本块）。

每个超边（hyperedge）：
$$ \tilde{e}j = (\Omega^{\text{rel}}j}, \mathcal{V}) $$}_j
（\(\Omega^{\text{rel}}_{\tilde{e}_j}\) 为自然语言描述的关系，\(\mathcal{V}_{\tilde{e}_j}\) 为从属节点集合，\(|\mathcal{V}_{\tilde{e}_j}| \geq 2\)）。

超边天然支持高阶（n-ary）关联，远超传统图的二元边（对应论文Figure 1 (ii)）。

3.4 Adaptive Memory-Based Evidence Retrieval（基于记忆的自适应证据检索）

当 \(\mathcal{M}^{(t)}\) 不足时，LLM 生成子查询 \(\mathcal{Q}^{(t)}\)，并根据查询目标自适应选择检索范围：
- 局部调查（Local Investigation）（针对已有超边 \(\tilde{e}_j\)）：以 \(\mathcal{V}_{\tilde{e}_j}\) 为锚点，检索其邻居：
$$ \mathcal{V}q = \mathcal{R}}(\mathcal{V{\tilde{e}_j})}(q), \quad \mathcal{N}(\mathcal{V}j}) = \bigcup{\tilde{e}_j}} \bigl( \mathcal{N}}^{(t)}}(v) \cup \mathcal{N{\mathcal{G}}(v) \bigr) $$
（\(\mathcal{N}_{\mathcal{M}^{(t)}}(v)\) 为记忆内邻居，\(\mathcal{N}_{\mathcal{G}}(v)\) 为原图邻居）。
- 全局探索（Global Exploration）（探索记忆外内容）：
$$ \mathcal{V}_q = \mathcal{R}}(\mathcal{M}^{(t)})}(q), \quad \mathcal{C}(\mathcal{M}^{(t)}) = \mathcal{V{\mathcal{G}} \setminus \mathcal{V} $$ }^{(t)}

检索完成后，获取关联边和文本块，并触发记忆演化（转至3.5节）。

3.5 Dynamic of Memory Evolving（记忆演化的动态机制）

检索到新信息后，LLM 对 \(\mathcal{M}^{(t)}\) 进行三种操作，演化得到 \(\mathcal{M}^{(t+1)}\)（对应论文Figure 1 (ii) 和 Figure 2 的具体示例）：
- Update（更新）：若检索信息表明某现有超边的描述需修正，则仅修改 \(\Omega^{\text{rel}}_{\tilde{e}_j}\)，不改变其从属节点集合。
- Insertion（插入）：将检索信息中适合作为新记忆点的内容创建新超边，插入 \(\tilde{\mathcal{E}}_{\mathcal{M}}\)。
- Merging（合并）：在更新和插入后，LLM 检查现有记忆点，选择性地合并语义/逻辑上可构成更高阶单元的超边。对目标查询 \(\hat{q}\)，假设合并 \(\tilde{e}_i\) 和 \(\tilde{e}_j\) 为 \(\tilde{e}_k\)：
$$ \Omega^{\text{rel}}{\tilde{e}_k} \leftarrow \mathrm{LLM}(\Omega^{\text{rel}}i}, \Omega^{\text{rel}}j}, \hat{q}) \tag{8} $$
$$ \mathcal{V}k} = \mathcal{V}i} \cup \mathcal{V} $$}_j
新超边 \(\tilde{e}_k\) 加入当前记忆的超边集合。

通过合并操作，记忆逐步从“原始事实堆积”演变为高阶关联结构，显著提升复杂关系建模能力。

3.6 Memory-Enhanced Response Generation（记忆增强的响应生成）

当达到最大交互步数或LLM判定当前记忆 \(\mathcal{M}^{(t)} = (\mathcal{V}_{\mathcal{M}^{(t)}}, \tilde{\mathcal{E}}_{\mathcal{M}^{(t)}})\) 已充分时，直接生成最终答案。
输入LLM的内容包括：
- 所有超边描述 \(\tilde{\mathcal{E}}_{\mathcal{M}^{(t)}}\)（即所有记忆点的关系描述）；
- 当前记忆中所有实体 \(\mathcal{V}_{\mathcal{M}^{(t)}}\) 关联的原始文本块。

这种设计确保生成阶段既能利用高阶结构化知识，又能回溯原始证据，实现更可靠的全局理解。

总结：HGMEM的核心在于将记忆建模为可动态演化的超图，通过Update/Insertion/Merging三种操作实现高阶关联的逐步构建，同时在检索时采用记忆引导的自适应策略，最终在生成阶段提供结构化+原始证据的增强输入。这与传统“被动事实堆积”的记忆设计形成鲜明对比，专为多步RAG的长上下文复杂推理任务量身定制。
